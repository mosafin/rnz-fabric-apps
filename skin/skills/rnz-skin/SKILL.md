# RNZ skin (existing apps)

This app keeps its own structure, layout, components and logic. The RNZ skin only changes how it
looks: colours, fonts and font weights. `src/rnz-skin.css` maps the app's own design tokens to RNZ
values, so anything that uses those tokens is already on brand. Your job is to keep it that way.

## The one rule

**Change values, never structure.** When you bring something on brand, swap the colour, font or
weight value for an RNZ token and change nothing else: no markup, layout, spacing, sizes,
components, props, logic, copy, file names or file moves.

## Use these, in this order

1. **The app's own tokens** (Tailwind classes such as `bg-primary`, `text-foreground`, `bg-card`,
   `bg-muted`, `border-border`, `text-muted-foreground`, or CSS variables such as
   `var(--color-primary)`). The skin already maps them to RNZ values.
2. **RNZ variables from `src/rnz-skin.css`**, when the app has no token for it:

| Use | Variable | Value |
|---|---|---|
| Primary action, key emphasis, links, focus ring, errors | `var(--rnz-red)` | #CF142B |
| Hover and pressed on red only | `var(--rnz-red-pressed)` | #A51022 |
| All text, icons, input borders | `var(--rnz-grey)` | #666666 |
| Page and card background | `var(--rnz-white)` | #FFFFFF |
| Light surface: panels, table headers, hover rows | `var(--rnz-light)` | #F5F5F5 |
| Dividers and card outlines (never behind text) | `var(--rnz-border)` | #E0E0E0 |
| Chart series 3 to 5, status bars and icons | `var(--rnz-muted-blue)`, `var(--rnz-muted-teal)`, `var(--rnz-muted-green)` | #4F8FAC, #428994, #7B9C6B |
| Chart series 6 to 10 (label them directly) | `var(--rnz-blue)`, `var(--rnz-teal)`, `var(--rnz-green)`, `var(--rnz-amber)`, `var(--rnz-pink)` | #5EA8E6, #00A9C5, #96C120, #FFC13D, #FF9AA8 |
| Font | `var(--rnz-font)` | Frutiger, then Arial |
| Weights | `var(--rnz-weight-light)`, `var(--rnz-weight-regular)`, `var(--rnz-weight-bold)` | 300, 400, 700 |

## Colour rules

- Red, white and grey make up most of every screen. Red is for the one primary action and key
  emphasis, not decoration.
- **No black or near-black** (#000, #111, #1A1A1A, #222, #333): use Ricoh Grey #666666.
- White text only on Ricoh Red or Ricoh Grey. Never grey text on a pastel or coloured fill.
- Charts: series order red, grey, muted blue, muted teal, muted green, then blue, teal, green,
  amber, pink. Highlight the key series in red and push the rest to grey when one number matters.
- Status always has an icon or text as well as colour.
- Light theme. Don't add dark surfaces, dark headers or dark bands.

## Type rules

- Frutiger, then Arial. **Never add Google Fonts or any font link**, and never pick another font.
- Weights 300 (large figures only), 400 (body) and 700 (headings, labels, buttons). Replace 500,
  600, 800 and 900 with 400 or 700.
- Don't change font sizes or line heights; that's structure.

## Logo

- The RICOH logo is always the **lock-up** (logo with the "imagine. change." tagline):
  `public/brand/RICOH-Logo_sRGB_full-colour.png`, shown through `<RicohLockup />` from
  `src/rnz-lockup.tsx`, at least 80px wide (40px tall). Never the logo without the tagline, never
  cropped, recoloured, redrawn or typed as text, and never a favicon.
- Adding the lock-up to an existing header is a small structural change: only do it when asked.

## Working through rnz/skin-report.md

1. Take each listed value in the app's own files and replace it with the suggested token (or a
   better-fitting token from the table above, if the suggestion is clearly wrong for its role).
2. Leave values inside `src/rnz-skin.css` and anything under `rnz/` alone.
3. Leave app-specific colour tokens that carry meaning the RNZ palette doesn't cover (for example
   a status colour set) unless asked; list them for the person instead.
4. Run `npm run rnz:skin-check`, then the app's build and tests. Fix only what you broke.

## Never

- Never edit `src/rnz-skin.css`, `rnz/skin.json` or `rnz/skin-check.mjs` by hand. They are
  regenerated by the RNZ skin tool (rnz-fabric-apps).
- Never rename or move files.
- Never restructure screens to "make them more RNZ". That's a separate, explicit request.
